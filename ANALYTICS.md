# Самостоятельная аналитика BoyGame

Аналитика необязательная и выключена по умолчанию. В приложении нет встроенного центрального сервера: каждая установка может подключить собственный API и хранит статистику отдельно. Без согласия родителя события не отправляются.

## Что считается

- **Новые игроки за день** — профили, для которых сервер впервые получил запуск игры в этот день.
- **Активные игроки за день** — уникальные профили, запустившие хотя бы одну игру в этот день. Новые игроки входят в это число.
- **Всего игроков** — уникальные профили, чьи записи ещё хранятся на этом сервере.
- **Популярные игры** — число запусков каждой игры за последние 30 дней.

День считается по UTC. Событие создаётся при запуске игры, а не при её завершении. ID профиля — случайный постоянный UUID, создаваемый только после согласия. Он не содержит имя или возраст, но остаётся псевдонимным идентификатором. Если очистить данные браузера или создать профиль на другом устройстве, игрок может посчитаться новым.

В SQLite сохраняются только профильный UUID, дата первого запуска и счётчики запусков по дням и играм. Точные времена и результаты игр не записываются. Запуски без сети не ставятся в очередь. Родитель может отключить сбор и удалить данные профилей с текущего устройства через API; при отсутствии сети приложение сохранит запрос на удаление и покажет кнопку повтора. Удалённые профили больше не входят в показатель общего числа игроков.

## Запуск API

Нужны Python 3.10+ и SQLite. API использует только стандартную библиотеку Python. Его следует запускать за HTTPS reverse proxy; порт API не открывайте напрямую в интернет. Создайте отдельного системного пользователя и каталог базы данных:

```sh
sudo useradd --system --create-home --home-dir /var/lib/boygame-analytics --shell /usr/sbin/nologin boygame-analytics
sudo install -d -o boygame-analytics -g boygame-analytics -m 700 /var/lib/boygame-analytics
openssl rand -hex 32
```

Сохраните сгенерированный секрет в закрытом env-файле менеджера процессов и задайте:

- `BOYGAME_ANALYTICS_DB=/var/lib/boygame-analytics/analytics.sqlite3`
- `BOYGAME_ANALYTICS_TOKEN` — сгенерированный секрет (не короче 24 символов)
- `BOYGAME_ANALYTICS_ORIGINS=https://games.example.com`
- `BOYGAME_ANALYTICS_HOST=127.0.0.1`
- `BOYGAME_ANALYTICS_PORT=8766`

Для нескольких сайтов перечислите точные origin через запятую, например `https://games.example.com,https://play.example.net`. Не используйте `*`. Запустите `python3 /полный/путь/к/BoyGame/analytics/server.py` от имени пользователя `boygame-analytics` и настройте автоматический запуск через выбранный менеджер процессов. Секрет API храните только в окружении сервера, никогда не помещайте его в JavaScript или репозиторий.

Пример блока nginx на том же сервере:

```nginx
location /api/v1/ {
    access_log off;
    proxy_pass http://127.0.0.1:8766;
    proxy_set_header Host $host;
}
```

Для другого reverse proxy настройте HTTPS, передачу пути `/api/v1/...` без изменений и отключение либо минимизацию access-логов. Приложение не отправляет IP в теле запроса, но сам хостинг и прокси могут вести собственные технические журналы.

Публичный endpoint приёма запусков ограничен точными CORS-origin, но CORS не является аутентификацией: запросы могут подделывать вне браузера. Для публичной установки настройте на reverse proxy ограничение частоты запросов к `POST /api/v1/events`. Чтение статистики всегда защищено серверным токеном.

## Подключение приложения

В `js/analytics-config.js` укажите публичный адрес API и опубликованные владельцем правила обработки данных:

```js
window.BOYGAME_ANALYTICS_CONFIG = {
  enabled: true,
  endpoint: 'https://games.example.com/api/v1',
  privacyUrl: 'https://games.example.com/privacy.html'
};
```

Эти настройки публичны и не должны содержать секретов. Каждый самостоятельный владелец выбирает свой API, политику, сервер и допустимые условия сбора. На GitHub Pages можно разместить только статическую часть; API и SQLite должны работать на отдельном сервере. Внесённые здесь изменения включают backend-пример, но не включают сбор данных для текущего сайта, пока конфигурация остаётся выключенной.

## Админ-панель

Откройте `#admin`, пройдите локальный экран входа и введите `BOYGAME_ANALYTICS_TOKEN` в поле серверного ключа. Ключ передаётся только API-запросу статистики и не сохраняется браузером. Настоящую защиту данных обеспечивает серверный ключ; локальный пароль в JavaScript не является секретом.

## Настройки приватности владельца

Псевдонимные идентификаторы и статистика остаются в базе до удаления родителем через API или ручного удаления владельцем. Владелец установки должен установить подходящий срок хранения, разместить понятные правила обработки, выбрать место хранения и настроить резервные копии и доступ к базе. Пример API предоставляет основу для самостоятельной установки, но не гарантирует соответствие законам всех стран.
